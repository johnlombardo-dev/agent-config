# UI copy

Help the user understand the current state, predict an action's result, and recover when something fails.

## Requirements

- Name controls after the action they perform or the state they select.
- Make labels and helper text explain behavior. Do not use product slogans inside controls.
- Keep one term for each product concept. Do not cycle synonyms to avoid repetition.
- State important scope in the interface, such as whether a change affects one item, a workspace, or every user.
- Name irreversible or destructive outcomes before confirmation.
- Write errors that state what happened and what the user can do next.
- Write empty states that explain why the area is empty and offer a valid next action.
- Keep text short only after it remains unambiguous.
- Do not call a task easy, simple, or obvious.

## Audit

- Can the user predict what happens before activating the control?
- Does the resulting state use the same terms as the initiating control?
- Can the user recover from failure without guessing?
- Does any text advertise the product instead of helping with the current task? Remove it.
