# UI copy

Help the user understand the current state, predict an action's result, and recover from failure.

## Requirements

- Name controls after the action they perform or the state they select.
- Use labels and helper text to explain behavior. Keep product slogans out of controls.
- Use one term for each product concept. Do not cycle synonyms to avoid repetition.
- State important scope in the interface, including whether a change affects one item, a workspace, or every user.
- Name irreversible or destructive outcomes before confirmation.
- Write errors that state what happened and what the user can do next.
- Write empty states that explain why the area is empty and offer a valid next action.
- Shorten text only after its meaning is unambiguous.
- Do not call a task easy, simple, or obvious.

## Audit

- Can the user predict what happens before activating the control?
- Does the resulting state use the same terms as the initiating control?
- Can the user recover from failure without guessing?
- Does every piece of text help with the current task rather than advertise the product? Remove any that does not.
